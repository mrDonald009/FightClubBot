# Описание архитектуры и логики связей FightClubBot

## 📋 Общая структура данных

### 1. **Тренер (User с role='coach')**

**Характеристики:**
- `id` - уникальный идентификатор
- `telegram_id` - ID в Telegram
- `role = 'coach'` - роль тренера
- `sport_type` - вид спорта (MMA, Тайский Бокс)
- `is_active` - активен ли тренер

**Связи:**
- Создает спортсменов через `Athlete.created_by` (один-ко-многим)
- Проводит тренировки через `Training.coach_id` (один-ко-многим)
- Отмечает посещения через `Attendance.marked_by` (один-ко-многим)

**Функциональность:**
- Добавление спортсменов
- Просмотр списка своих спортсменов (фильтрация по `created_by` и `sport_type`)
- Просмотр календаря тренировок
- Отметка посещений спортсменов

---

### 2. **Спортсмен (Athlete)**

**Характеристики:**
- `id` - уникальный идентификатор
- `user_id` - связь с User (может быть NULL, если нет Telegram аккаунта)
- `full_name` - полное имя
- `phone` - телефон
- `sport_type` - вид спорта (MMA, Тайский Бокс)
- `age_group` - возрастная группа (children, adults)
- `created_by` - ID тренера, который добавил спортсмена (FK → User.id)
- `subscription_id` - ID текущего абонемента (FK → Subscription.id, **один-к-одному**, unique=True)

**Связи:**
- **Один-к-одному с абонементом** через `subscription_id`
  - `athlete.subscription` → один Subscription или None
  - Обратная совместимость: `athlete.current_subscription` (property)
- **Многие-к-одному с тренером** через `created_by`
  - `athlete.coach` → User (тренер)
- **Многие-к-одному с User** через `user_id` (опционально)
  - `athlete.user` → User (если есть Telegram аккаунт)

**Важно:**
- У спортсмена может быть **только один активный абонемент** (связь один-к-одному)
- При создании нового абонемента старый автоматически деактивируется
- Спортсмен привязан к тренеру через `created_by`

---

### 3. **Абонемент спортсмена (Subscription)**

**Характеристики:**
- `id` - уникальный идентификатор
- `athlete_id` - ID спортсмена (FK → Athlete.id)
- `subscription_type` - тип абонемента ('monthly' - 12 тренировок, 'single' - 1 тренировка)
- `start_date` - дата начала действия
- `end_date` - дата окончания действия
- `trainings_total` - всего тренировок (12 для месячных, 1 для разовых)
- `trainings_remaining` - осталось тренировок
- `is_active` - активен ли абонемент
- `total_restored` - всего восстановлено тренировок
- `restored_this_month` - восстановлено в этом месяце
- `created_at` - дата создания

**Связи:**
- **Один-к-одному со спортсменом** через `Athlete.subscription_id`
  - `subscription.athlete` → один Athlete (viewonly, через primaryjoin)
- **Один-ко-многим с посещениями** через `Attendance.subscription_id`
  - `subscription.attendances` → список Attendance

**Логика работы:**
- При создании месячного абонемента:
  - Автоматически создаются тренировки по расписанию на период действия
  - Первая тренировка в день активации списывается автоматически (attended=False) **только если день активации является тренировочным днем по расписанию**
- При создании нового абонемента:
  - Старый абонемент деактивируется (`is_active = False`)
  - Старый абонемент отвязывается от спортсмена (`athlete.subscription_id = None`)
  - Новый абонемент привязывается (`athlete.subscription_id = new_subscription.id`)

**Валидация при создании:**
- Проверка на дубликаты ФИО - нельзя создать спортсмена с существующим ФИО
- Проверка на дубликаты телефона - нельзя создать спортсмена с существующим телефоном
- Проверка комбинации ФИО + телефон - нельзя создать спортсмена с такой же комбинацией

---

### 4. **Календарь тренера**

**Логика работы:**

#### 4.1. Отображение календаря
- Показывает месяц с тренировочными днями
- Дни с тренировками по расписанию помечаются круглыми скобками `(день)`
- Сегодняшний день помечается квадратными скобками `[день]`
- Навигация по месяцам (предыдущий/следующий)

#### 4.2. Расписание тренировок
Определяется в `TrainingManager.TRAINING_SCHEDULE`:
- **MMA:**
  - Дети: Пн, Ср, Пт в 18:00
  - Взрослые: Пн, Ср, Пт в 20:00
- **Тайский Бокс:**
  - Дети: Вт, Чт, Сб в 18:00
  - Взрослые: Вт, Чт, Сб в 20:00

#### 4.3. Клик по дате в календаре
При клике на дату показывается:

1. **Если есть тренировки в базе данных:**
   - Список тренировок на эту дату
   - Для каждой тренировки показываются спортсмены с активными абонементами:
     - Фильтрация по `sport_type` и `age_group` тренировки
     - Проверка, что дата тренировки попадает в диапазон действия абонемента:
       - `Subscription.start_date <= дата тренировки`
       - `Subscription.end_date >= дата тренировки`
     - Показывается статус посещения (✅ присутствовал, ❌ отсутствовал)

2. **Если тренировок нет, но есть расписание:**
   - Показываются спортсмены по расписанию
   - Фильтрация:
     - По виду спорта тренера (`user.sport_type`)
     - По возрастной группе
     - По тренеру (если `user.role == 'coach'`, то только `Athlete.created_by == user.id`)
     - С активными абонементами на эту дату
   - Показывается статус посещения (если есть запись Attendance)

#### 4.4. Связь с тренером
- Тренер видит только свои тренировки (`Training.coach_id == user.id`)
- Тренер видит только своих спортсменов (`Athlete.created_by == user.id`)
- Администратор видит все тренировки и всех спортсменов

---

### 5. **Тренировка (Training)**

**Характеристики:**
- `id` - уникальный идентификатор
- `sport_type` - вид спорта
- `age_group` - возрастная группа
- `training_date` - дата и время тренировки
- `is_cancelled` - отменена ли тренировка
- `coach_id` - ID тренера, проводящего тренировку (FK → User.id, nullable)

**Связи:**
- **Многие-к-одному с тренером** через `coach_id`
  - `training.coach` → User (тренер)
- **Один-ко-многим с посещениями** через `Attendance.training_id`
  - `training.attendances` → список Attendance

**Логика создания:**
- При создании месячного абонемента автоматически создаются тренировки по расписанию
- Тренировки создаются с `coach_id = athlete.created_by` (тренер спортсмена)
- Тренировки создаются только в дни, указанные в расписании

---

### 6. **Посещение (Attendance)**

**Характеристики:**
- `id` - уникальный идентификатор
- `athlete_id` - ID спортсмена (FK → Athlete.id)
- `training_id` - ID тренировки (FK → Training.id)
- `subscription_id` - ID абонемента (FK → Subscription.id)
- `attended` - присутствовал ли (True) или отсутствовал (False)
- `marked_by` - ID пользователя, который отметил (FK → User.id)
- `was_restored` - была ли восстановлена тренировка
- `restoration_reason` - причина восстановления

**Связи:**
- **Многие-к-одному со спортсменом** через `athlete_id`
- **Многие-к-одному с тренировкой** через `training_id`
- **Многие-к-одному с абонементом** через `subscription_id`
- **Многие-к-одному с пользователем** через `marked_by`

**Логика работы:**
- При создании месячного абонемента автоматически создается первая запись Attendance (attended=False)
- При отметке посещения тренером:
  - Если присутствовал (`attended=True`) и тренировка еще не списана - списывается одна тренировка
  - Если отсутствовал (`attended=False`) - тренировка не списывается (неиспользовано)

---

## 🔄 Процессы и потоки данных

### Процесс 1: Добавление спортсмена тренером

1. Тренер выбирает "👥 Добавить спортсмена"
2. Вводит данные спортсмена (ФИО, телефон, медицинская информация, возрастная группа)
3. Выбирает тип абонемента (Месячный/Разовый)
4. **Для месячного абонемента:**
   - Создается абонемент с 12 тренировками
   - Автоматически создаются тренировки по расписанию на месяц
   - Первая тренировка списывается автоматически (attended=False)
   - Абонемент привязывается к спортсмену (`athlete.subscription_id = subscription.id`)
5. **Для разового абонемента:**
   - Выбирается дата тренировки
   - Создается абонемент с 1 тренировкой
   - Абонемент привязывается к спортсмену

### Процесс 2: Просмотр календаря тренером

1. Тренер выбирает "📅 Мой календарь"
2. Показывается календарь текущего месяца
3. Дни с тренировками по расписанию помечаются `(день)`
4. При клике на дату:
   - Если есть тренировки в БД - показываются спортсмены с активными абонементами
   - Если нет тренировок - показываются спортсмены по расписанию с активными абонементами
   - Фильтрация: только спортсмены тренера (`Athlete.created_by == user.id`)
   - Фильтрация: только активные абонементы на эту дату

### Процесс 3: Отметка посещения

1. Тренер выбирает спортсмена для отметки
2. Выбирает тренировку из списка последних 5 тренировок
3. Выбирает статус: "✅ Был" или "❌ Не был"
4. **Если "Был":**
   - Создается/обновляется запись Attendance (attended=True)
   - Если тренировка еще не списана - списывается одна тренировка из абонемента
5. **Если "Не был":**
   - Создается/обновляется запись Attendance (attended=False)
   - Тренировка не списывается (неиспользовано)

### Процесс 4: Автоматическое списание тренировок

1. При создании месячного абонемента:
   - Автоматически создаются тренировки по расписанию на период действия
   - Первая тренировка списывается автоматически **только если день активации является тренировочным днем** (attended=False)
2. При открытии карточки абонемента вызывается `auto_deduct_daily_trainings()`
3. Для всех активных абонементов:
   - Проверяется, сегодня ли тренировочный день по расписанию
   - Если да - создается запись Attendance (attended=False)
   - Списывается одна тренировка из абонемента
   - Создается Training (если еще не создана)

---

## 🔗 Схема связей (один-к-одному)

```
User (тренер)
  │
  ├─→ Athlete (created_by) [один-ко-многим]
  │     │
  │     └─→ Subscription (subscription_id) [один-к-одному] ⭐
  │           │
  │           ├─→ Attendance (subscription_id) [один-ко-многим]
  │           │     │
  │           │     └─→ Training (training_id) [многие-к-одному]
  │           │           │
  │           │           └─→ User (coach_id) [многие-к-одному]
  │           │
  │           └─→ Athlete (athlete_id) [один-к-одному, viewonly]
  │
  └─→ Training (coach_id) [один-ко-многим]
```

**Ключевая особенность:**
- ⭐ **Связь Athlete ↔ Subscription один-к-одному** через `Athlete.subscription_id`
- У спортсмена может быть только один активный абонемент
- При создании нового абонемента старый автоматически деактивируется

---

## 📊 Фильтрация и права доступа

### Тренер (role='coach'):
- Видит только своих спортсменов: `Athlete.created_by == user.id`
- Видит только свои тренировки: `Training.coach_id == user.id`
- Видит только спортсменов своего вида спорта: `Athlete.sport_type == user.sport_type`
- Может отмечать посещения только для своих тренировок

### Администратор (role='admin'):
- Видит всех спортсменов
- Видит все тренировки
- Может отмечать посещения для любых тренировок

---

## 🎯 Ключевые моменты

1. **Связь один-к-одному:** У спортсмена может быть только один активный абонемент через `subscription_id`
2. **Автоматическое списание:** При создании месячного абонемента автоматически создаются тренировки и списывается первая
3. **Расписание:** Определяется в `TrainingManager.TRAINING_SCHEDULE` по виду спорта и возрастной группе
4. **Календарь:** Показывает спортсменов с активными абонементами, у которых дата тренировки попадает в диапазон действия абонемента
5. **Фильтрация по тренеру:** Тренер видит только своих спортсменов и свои тренировки
